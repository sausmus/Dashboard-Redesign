TEACHER DASHBOARD PROTOTYPE 5 — ONE-STUDENT ASSIGNMENT ATTACHMENT TEST

This package replaces the earlier separate-Classroom-material workflow.
NO separate Classwork material or post is created by this version.
Existing Docs, assignments, local Dashboard records and mappings are preserved.
Previously created/deleted Classroom materials are not touched or recreated.

TEST FIRST
1. Install all changed files, including both shared service files. Reload Students.
2. Choose the intended period, then Timeliness -> gear.
3. Review the saved term and Record school year. Save changes before testing.
4. Under Test with one student, choose exactly one Classroom-linked student.
5. Click Test selected student only and confirm the named student.
6. In the EXISTING Timeliness assignment, open that student's work and check
   for their Timeliness Record link. The student should be able to view the Doc
   but not edit it. No additional Classwork post should appear.

The test runs record rewriting, attachment delivery, and grade synchronization
for ONLY the selected student. It may read class roster/submission metadata to
identify them, but does not write grades, Docs, or attachments for classmates.
It reuses that student's existing teacher-owned Doc when present. A new Doc
is created only if that student's record identity has no existing Doc.
The test explicitly includes Docs and attachments even if regular-sync options
are disabled. It uses SAVED settings, not unsaved gear checkbox/year edits.
For complete success, the student must have a TURNED_IN or RETURNED submission.

Full-class record attachment sync is blocked until one student's test succeeds
for that course, assignment, term, and school year. After success, full-class
sync remains a separate explicit action; it is never started automatically.
Verify the student-facing result before choosing the full-class action.
Grade-only sync remains available by disabling Doc updates in the gear.
The gear includes a copyable Last sync result field, retained for this page
session, with detailed errors. Grade success can coexist with attachment failure;
that student stays pending and the test does not unlock class attachment sync.

ATTACHMENT IMPLEMENTATION
Uses Classroom studentSubmissions.modifyAttachments to add a Doc link inside
the student's existing assignment submission. Teacher-owned Docs stay reader-
shared with the student. No template or Make a copy for each student is needed.
Reads existing submission attachments before adding; matching Doc links/files
are reused, unrelated attachments remain unchanged, and no attachment is removed.
The 20-attachment API limit is checked. Record identity remains school year +
course + grading term + Google student ID, independent of assignment recreation.
Docs are rewritten with current score and complete late-work history on sync.
Drive appProperties recover the same Doc after lost local Doc mappings.
Known inaccessible/trashed/incorrectly owned Docs fail rather than create a
replacement. Unexpected sharing stops rewriting; student writer access is
downgraded to reader. Revision control protects against concurrent Doc edits.

Google requires the same Cloud project/OAuth client project that created the
assignment. An attachment permission failure is reported without making a new
assignment or falling back to Classwork posts. Whether your existing assignment
accepts teacher-side attachment delivery must be confirmed by the live test.

GOOGLE SETUP
Keep the existing OAuth client and Classroom assignment mappings. Enable Drive
API and Docs API in that same Cloud project alongside Classroom API.
Doc sync uses drive.file and classroom.profile.emails plus the existing
classroom.coursework.students scope. classroom.courseworkmaterials is no longer
requested or used. Previously granted Google permissions are not automatically
revoked by installing this patch. Tokens remain memory-only.

OTHER P5 FEATURES RETAINED
Manual Participation/Timeliness grade sync uses existing grade calculations,
updates assigned/draft grades, and returns turned-in submissions. Dashboard
remains source of truth; Classroom grades are never imported. Per-student
receipts show Needs setup / Changes not synced / Synced and stay pending after
skips, failures or local edits. Status represents a successful export, not a live
audit of external edits in Classroom or Drive. No background Google writes.
Full-class sync applies to the selected period's roster, regardless of search.
Students waiting for first Turn In are reported; eligible Doc updates may still
run even if the grade cannot yet be returned.

Search persists across tabs without switching to Roster. Roster, Participation
and Timeliness show matches across active periods with correct class identity.
Selector shows search matches and a Select student action; random selection uses
matches in the current period without shrinking the stored pool.
Student cards retain normal responsive width when results are filtered.
Late-work modal and profile history both offer confirmed per-entry deletion,
using the existing removeTimelinessEntry API with immediate score/history refresh.

STORAGE
shared/dashboard-data.js remains byte-identical to the supplied corrected P4.4.
No existing storage key/schema, score, roster or assignment mapping is cleared,
migrated or reset. The isolated teacherDashboard.studentProgressSync.v1 key
retains Docs/receipts/options and adds:
 - options.attachments (replaces the UI's obsolete private-post option)
 - attachmentTests keyed by school year/course/assignment/term
 - per-Doc attachedAssignments timestamps
Old options.links/materialId/linkedAt fields are retained but ignored, and are
never used to create/update deleted materials. teacherDashboard.progressDocsConsent.v1
remains only a consent hint; no access token is persisted.
Save the correct Record school year once per academic year; changing it selects
a different set of record identities without resetting Dashboard scores.
Web Locks serialize sync across same-origin tabs; use HTTPS or localhost and a
current browser. Use one device for sync at a time: Drive creation has no unique-
key transaction across devices. Keep the same OAuth project for recovery.

PACKAGES AND VALIDATION
Changed ZIP contains students.html, shared/classroom-service.js,
shared/student-progress-service.js and this PROTOTYPE-5-NOTES.txt. Install all four.
Full ZIP contains the complete latest repo, including prior search/card fixes.
All 27 JavaScript blocks parsed. Tests with actual DashboardData and mocked Google
responses verified one-student write scope, initial class-sync gate, attachment
deduplication, preserving unrelated attachments, repeat Doc reuse/recovery,
manual-only writes, deletion/data preservation and pending/failure statuses.

required verification of your assignment's permissions and student visibility.
